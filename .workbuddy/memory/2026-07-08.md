## 侧边栏按钮点不动（drag-region 拦截点击）17:09 轮次
- 用户根因定位：`.drag-region`(127行) 是 `-webkit-app-region: drag`；`.brand-row`/`.top-actions` 有 no-drag，但 `.sidebar-toggle` 内的 **SVG 图标**没有 no-drag → WKWebView 把对图标的点击当窗口拖拽拦截，按钮点不动。
- 注意：`.sidebar-toggle` 容器本身其实有 no-drag(133行)，但 no-drag 不会可靠地级联到 SVG 子元素，所以点击图标仍被吞。
- 修复：在 `.sidebar-toggle:hover` 后加一条通用规则 `.drag-region button, .drag-region button *, .topbar button, .topbar button * { -webkit-app-region: no-drag; }`，覆盖标题栏所有按钮及其图标，根除此类名点击失效问题。
- 另：两个切换按钮图标当前是 panel 图标(`<rect x=3 y=3 w=18 h=18 rx=2/><line x1=9.../>`)，清晰表示侧边栏，保留。
- 流程同前：gen:renderer → build → pkill laufey_webview → open Pi-a.app。curl 运行端口验证 no-drag 规则存在、panel 图标×2、plus 0 次。

## 侧边栏开关仍点不动 → 彻底修复 17:14 轮次
- 上一轮的 no-drag 规则其实已生效（`.topbar > *` 也给了 topbar 按钮 no-drag，且工件/导出等按钮正常工作，证明本 app 的 no-drag 是生效的）。所以"点不动"不是单纯 drag 区域拦截，而是**之前用 document 全局委托 + 对 SVG 点击目标调 `e.target.closest('#sidebar-toggle,#sidebar-expand')`** 的边界情况把点击吞了（SVG 元素上 closest 行为/事件目标不确定）。
- 最终稳健方案（两处）：
  1. 结构上把 `#sidebar-toggle` 从 `.drag-region` 里挪出来，改为 `.sidebar-head`(普通 flex 行，非 drag 区) 的直接子元素；`.drag-region` 现在只包裹 brand-row + top-actions，仍是拖拽区。从结构上彻底排除原生拖拽拦截。
  2. JS 把 `document.addEventListener('click', 委托)` 改成 `bindSidebarToggle()`：直接 `getElementById('sidebar-toggle'/'sidebar-expand').addEventListener('click', ...)`，显式 preventDefault+stopPropagation。不再依赖 ontarget.closest。
- 经验：WKWebView 里对 SVG 图标按钮用 document 事件委托 + closest 不可靠，应直接绑到按钮元素。重建后 curl 运行端口确认 bindSidebarToggle×2、sidebar-head×2、旧 closest 委托 0 次。
