## 一、产品形态

### 1.1 三种存在形态（一个产品，三种入口）

```
┌─────────────────────────────────────────────────────────────┐
│                    WorkBuddy 的三种存在形态                    │
├──────────────┬──────────────┬───────────────────────────────┤
│  ① 主工作台   │  ② 速唤浮窗   │  ③ 后台 Agent                  │
│  (主窗口)     │  (Spotlight) │  (无界面)                      │
│              │              │                               │
│  完整三栏布局  │ ⌥Space 唤起   │ 技能/自动化触发                │
│  会话 + 工件  │ 当前上下文问答 │ 定时/事件驱动执行              │
│  技能/设置    │ 选区/屏幕感知 │ 静默干活, 完成通知             │
│              │              │                               │
│  → 深度工作   │  → 即时问答   │  → 自动化流水线                │
└──────────────┴──────────────┴───────────────────────────────┘
```

- **① 主工作台**：完整功能的窗口，深度工作场景（做一份周报、分析一份 Excel、生成一套 PPT）。借鉴腾讯 WorkBuddy 的三栏布局，但更克制。
- **② 速唤浮窗（Quick Buddy）**：全局热键（`⌥Space` / `Alt+Space`）唤起的小浮窗，感知当前 App / 选中文本 / 屏幕，做即时问答和轻量操作。对标 Raycast / ChatGPT Desktop 的快捷入口。
- **③ 后台 Agent**：由"自动化"触发、无界面运行，干完活儿弹通知（"周报已生成在 ~/Documents/周报-07-04.docx"）。

### 1.2 主工作台布局（三栏）

参考截图（腾讯 WorkBuddy v0.5.17）的三栏范式，做更适合"文档/自动化"重心的调整：

```
┌─────────────┬───────────────────────────┬───────────────────┐
│  左:导航     │  中:对话 + 工件            │  右:上下文/工件    │
│  (200px)    │  (弹性)                    │  (320px,可折叠)   │
├─────────────┼───────────────────────────┼───────────────────┤
│ ➕ 新会话    │ ┌───────────────────────┐ │ ┌─ 工件区 ───────┐ │
│             │ │ 对话流                 │ │ │ 生成的文档预览  │ │
│ 💬 会话      │ │  user: 把这周数据出表  │ │ │ 表格/PPT 缩略图  │ │
│  · 周报      │ │  🤖: [调用 write_xlsx] │ │ │                │ │
│  · 数据分析  │ │      已生成销售周表.xlsx│ │ ├─ 选区/屏幕 ───┤ │
│             │ │      👀 点击预览 →     │ │ │ 当前选中的文本  │ │
│ 🧩 技能      │ │  ...                  │ │ │ 截图            │ │
│  · 周报生成  │ │                       │ │ ├─ 相关文件 ────┤ │
│  · PPT 制作  │ └───────────────────────┘ │ │ RAG 召回的文档  │ │
│             │ ┌───────────────────────┐ │ └────────────────┘ │
│ ⚡ 自动化    │ │ 输入框  [📎][🖥️][⏎]   │ │                    │
│  · 每天9点...│ └───────────────────────┘ │                    │
│  · 会议后... │                           │                    │
│             │                           │                    │
│ 📁 项目      │                           │                    │
│  · Q3 复盘   │                           │                    │
│             │                           │                    │
│ ⚙️ 设置      │                           │                    │
└─────────────┴───────────────────────────┴───────────────────┘
```

**设计取舍说明**（与腾讯 WorkBuddy 的区别）：
- **右栏"工件区"是核心创新**：agent 生成的文档/表格/PPT 不是塞在对话气泡里，而是有独立的预览/编辑面板，可直接在 WorkBuddy 内查看和迭代（"把第3张图换成柱状图"）。
- **左栏更克制**：去掉腾讯版的"专家/连接器"（我们不堆生态），只保留 会话 / 技能 / 自动化 / 项目 / 设置。
- **中栏的 `[🖥️]` 按钮**：一键把"当前屏幕/选区"作为上下文喂给 agent（对应支柱② OS 自动化）。

## 二、核心概念模型

### 2.1 五个一等概念

| 概念 | 是什么 | 类比 |
|------|--------|------|
| **会话 Conversation** | 一次有上下文的连续交互，可关联项目、文件、记忆 | ChatGPT 的对话 |
| **技能 Skill** | 可复用的能力包：prompt 模板 + 工具组合 + 示例。用户/社区可创建分享 | Claude 的 Project / GPTs |
| **自动化 Automation** | 触发器 + 动作：定时 / 事件（文件变化、剪贴板、热键）→ 执行某个技能或 agent 任务 | iOS 快捷指令的自动化 |
| **项目 Project** | 工作上下文的容器：关联一组文件、记忆、进行中的会话 | IDE 的 workspace |
| **记忆 Memory** | 跨会话持久的事实/偏好/笔记，agent 主动读写 | Claude 的 memory / ChatGPT memory |

### 2.2 概念之间的关系

```
        ┌──────────┐  包含   ┌──────────┐
        │  Project │────────→│ 会话×N    │
        │          │────────→│ 文件集    │
        │          │────────→│ 记忆切片  │
        └────┬─────┘
             │ 关联
        ┌────▼─────┐  实例化  ┌──────────┐  触发    ┌──────────────┐
        │  Skill   │────────→│ Agent任务 │←────────│ Automation   │
        │(技能模板)│         │(一次执行) │         │(定时/事件)    │
        └──────────┘         └─────┬────┘         └──────────────┘
                                   │ 读写
                              ┌────▼─────┐
                              │  Memory  │←──── 全局共享
                              └──────────┘
```

## 三、功能模块清单

按 MVP 优先级标注：**[MVP]** = 第一个版本必须有，**[P1]** = 紧随其后，**[P2]** = 远期。

### 3.1 对话与会话管理 [MVP]

- 流式对话、多轮上下文
- 会话列表、重命名、置顶、归档、搜索
- 会话内 @ 引用：`@文件` `@项目` `@技能` `@记忆`
- **消息树**（分支对话）：对某条回复重新生成，形成可切换的分支（pi 自带 message tree）
- 对话导出（Markdown / JSON）

### 3.2 文档工件区 [MVP]

- agent 产出的文档在右栏独立预览（docx/xlsx/pptx/pdf/markdown）
- **工件可迭代**：在输入框说"把标题改成XX""加一页总结"，agent 编辑现有工件而非新建
- 工件可"另存为""在 Finder/资源管理器中显示""用默认程序打开"
- 工件版本历史（每次迭代一个版本，可回退）

### 3.3 文档引擎（支柱③） [MVP-读写, P1-编辑]

详见 [04-文档处理引擎](./04-文档处理引擎.md)。核心能力：

| 能力 | MVP | P1 |
|------|-----|----|
| 读 docx/xlsx/csv/md | ✅ | |
| 读 pptx/pdf | ✅ | |
| 生成 docx/xlsx/pptx | ✅ | |
| 生成 pdf（via LibreOffice 转换） | | ✅ |
| **编辑** 现有 docx（模板填充） | ✅ docxtemplater | |
| **编辑** 现有 docx（自由编辑） | | ✅ python sidecar |
| **编辑** 现有 xlsx | ✅ umya-spreadsheet | |
| **编辑** 现有 pptx | | ✅ python sidecar |

### 3.4 技能系统 [MVP-内置, P1-自定义]

- **内置技能包**（开箱即用，体现"中文知识工作者"定位）：
  - 📊 周报/月报生成（读数据 → 出 docx）
  - 📈 数据分析出表（读 csv/xlsx → 分析 → 出 xlsx + 图表）
  - 🎨 PPT 制作（大纲 → pptx）
  - 📄 文档润色/改写/翻译（读 docx → 编辑 → 输出）
  - 🗂️ 会议纪要整理（文本/音频转写 → 结构化 docx）
  - 🔍 文档问答（对本地文件做 RAG）
- **自定义技能** [P1]：用户用自然语言描述 + 选工具 + 给示例，生成可复用技能；可导入/导出/分享
- **技能市场** [P2]：社区分享
- **格式兼容**：技能采用 `SKILL.md`（YAML frontmatter `name`/`description`/`allowed-tools` + Markdown + 可选 scripts/references），与 **WorkBuddy/CodeBuddy 及 agentskills.io 规范兼容**（见 [00](./00-WorkBuddy逆向调研.md)）。未来技能包可与该生态互通。pi 的 `Skill` 接口 + `formatSkillsForSystemPrompt()` 原生支持此格式。

### 3.5 OS 自动化（支柱②） [P1]

详见 [05-OS自动化与权限](./05-OS自动化与权限.md)。核心：

- **速唤浮窗**：`⌥Space` 唤起，感知当前 App/选区/屏幕
- **Computer Use**：截图 → 视觉理解 → 鼠标键盘操作（macOS 用 Accessibility API 优先，Windows 用 UIAutomation，退化为坐标点击）
- **剪贴板感知**：复制的内容自动进上下文
- **跨 App 编排**：读 App A → 处理 → 写入 App B
- **全局热键**：用户可配置

### 3.6 自动化与后台 Agent [P1]

- **触发器**：定时（cron）/ 事件（文件变化、剪贴板匹配、热键、系统事件如"锁屏"/"连接显示器"）
- **动作**：执行一个技能 / 一段 agent 任务
- **后台运行**：托盘常驻，无界面执行，完成弹系统通知
- 示例："每天 18:00 把今天的会议纪要整理成 docx 存到周报项目"
- **远期**：多 agent 并行/监督场景可借鉴 pi 官方新增的 `@earendil-works/pi-orchestrator`（supervisor 模式，0.80 引入，当前 experimental，MVP 不依赖）

### 3.7 记忆系统 [MVP-基础, P1-增强]

- **全局记忆**：跨所有会话的事实/偏好（"我是产品经理""我喜欢简洁的表格风格"）
- **项目记忆**：项目级上下文
- **记忆管理面板**：查看 / 编辑 / 删除 / 导出（解决"记忆不可控"痛点）
- agent 可主动调用 `memory.recall` / `memory.write` 工具
- 隐私：所有记忆本地存储，可一键清空/导出

### 3.8 模型管理 [MVP]

- 多 provider 配置：OpenAI / Anthropic / DeepSeek / GLM（智谱）/ Ollama（本地）
- 按"任务类型"路由：文档任务走 GLM/DeepSeek，代码任务走 Claude，隐私任务走本地 Ollama
- API Key 加密存储（系统钥匙串 keychain）
- 用量统计

### 3.9 设置与权限 [MVP]

- 文档访问范围（指定目录，默认 `~/Documents`、`~/Desktop`）
- OS 自动化权限开关（按能力粒度：截图 / 鼠标 / 键盘 / 剪贴板，默认全关）
- 数据流透明面板：本次任务"读了什么、发给了哪个模型、写了什么"
- 主题、字体、语言（中/英）

## 四、核心用户旅程

### 旅程 A：知识工作者做周报（主工作台，文档引擎主导）

```
1. 用户在速唤浮窗或主窗口说："帮我把这周的销售数据整理成周报"
2. agent: 调用 read_file 读 ~/Documents/销售明细.xlsx
   → 工件区弹出该 xlsx 的预览
3. agent: "我看到有 3 个 sheet，按产品线汇总对吗？"（澄清意图）
4. 用户: "对，再加一个环比图表"
5. agent: 调用 write_xlsx 生成 周报-07-04.xlsx（含图表）
   → 工件区切换到新文件预览
6. 用户: "再把要点写成 docx 周报"
7. agent: 调用 write_docx 生成 周报-07-04.docx
   → 工件区出现 docx 预览
8. 用户: "标题改成'销售周报-W27'，结尾加一段下周计划"
9. agent: 调用 edit_docx（python sidecar）原地编辑
   → 工件区刷新，版本历史 +1
10. 用户: 点"在 Finder 中显示" → 完成
```

**关键设计点**：第 8 步的"编辑"而非"重建"，是工件区 + 文档引擎的核心价值，也是大多数 AI 客户端做不到的。

### 旅程 B：速唤浮窗即时问答（OS 上下文感知）

```
1. 用户在看一份英文 PDF 论文，选中一段术语
2. ⌥Space 唤起浮窗 → 自动带入选区文本 + "当前在 PDF 阅读器"上下文
3. 用户: "这个词什么意思，用中文解释"
4. agent: 基于选区回答，无需粘贴
5. Esc 关闭，继续阅读
```

### 旅程 C：后台自动化（无人值守）

```
1. 用户配置自动化: 触发器=每天 18:00, 动作="整理今日会议纪要"
2. 后台 Agent 到点唤醒, 扫描今日日历/录音
3. 执行技能"会议纪要整理" → 生成 docx
4. 系统通知: "✅ 今日会议纪要已生成，点击查看"
```

## 六、关键交互原则

1. **工件优先（Artifact-first）**：文档产出物是一等公民，不是对话的附属。可预览、可迭代、可版本回退。
2. **上下文自感知**：速唤浮窗自动带入选区/屏幕/当前 App，减少用户粘贴。
3. **澄清而非臆测**：意图不明时 agent 先问（旅程 A 第 3 步），而非瞎猜后返工——这是"可靠"的体现。
4. **数据流可见**：每次 agent 调用工具，对话流里清晰展示"读了 X / 写了 Y / 调用了模型 Z"，对冲"AI 偷偷干活"的不信任。
5. **权限最小化默认**：OS 自动化能力默认全关，用到时即时申请（类似手机权限）。
6. **可中断**：任何 agent 任务可随时停止；长时间任务可后台化。
