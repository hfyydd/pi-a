# 01 · 市场调研与产品定位

## 一、市场全景：AI 桌面智能体的 2025-2026

行业有一条清晰的主线：**从"陪伴型 companion"到"能干活的 agent"**。

- **Upwork Uma** 明确把自己从 "work companion" 重新定位为 "always-on work agent"，能自主完成面试。
- **Zoom AI Companion 3.0**（Zoomtopia 2025）定位为 "ultimate intelligent work companion"。
- **Microsoft Copilot** → "indispensable work companion" + 新增 **Work IQ** 智能层（Ignite 2025）。
- Futurum Group 判断：到 2025 Q4，agent 平台已成"新的企业主战场"，向 **"agentic OS"（智能体操作系统）** 模式演进。

> ⚠️ **前车之鉴**：Inflection Pi（融了 $1.3B，最终团队被微软吸收）和 Arc Max（被弃用、公司转向 Dia）证明——**只有情绪陪伴/薄层 AI 没有真正动手能力的"companion"留不住用户**。市场要的是"可靠地干活"。

## 二、主要竞品分析

### 第一梯队：大厂桌面端

| 产品 | 强项 | 弱项 / 痛点 |
|------|------|-------------|
| **ChatGPT Desktop** | 全局热键 Option+Space、语音、Record Mode | **臃肿**：用户实测 ~3GB RAM；MCP 支持仍不全；2025-02 静默丢失用户长期记忆 |
| **Claude Desktop** | **MCP/Computer Use 最强**；.dxt 一键安装 MCP server；截图+鼠标键盘控制桌面 | 本质仍是聊天窗，agent 能力是"外挂"而非持久 OS 层 |
| **Microsoft Copilot** | OS 集成最深；Word/Excel/PPT 的 agent mode；Windows 把 MCP 做进系统层；Recall 屏幕记忆 | Recall 因隐私被强烈质疑；强绑 M365 生态 |
| **Gemini Desktop** | 屏幕分析强；Gemini 3；Gemini Spark 24/7 主动 agent | 被批"只是个 portal"；本地文件检索弱 |
| **Raycast** | 键盘驱动 OS 集成的标杆；扩展生态 | **Mac only**；AI 只是众多功能之一，非核心 |

### 第二梯队：远程操控 / 浏览器 companion

| 产品 | 定位 | 启示 |
|------|------|------|
| **Perplexity Comet** | AI 原生浏览器，后台 agent | 仅限浏览器内，非 OS 级 |
| **腾讯 WorkBuddy** ⭐ | **直接对标对象**：自然语言操控电脑、文件批量处理、生成文档/PPT/表格、Claw 远程驱动（企微/飞书/钉钉/QQ）、多模型（混元/DeepSeek/GLM） | **证明需求真实存在**；但绑定腾讯云/飞书生态 |

### 第三梯队：开源桌面客户端（生态最活跃的细分）

| 项目 | 栈 | 特点 |
|------|-----|------|
| **[Cherry Studio](https://github.com/CherryHQ/cherry-studio)** | Electron | MCP 集成最成熟；"all-in-one AI workstation"；知识库/RAG；r/LocalLLaMA 口碑最佳 |
| **[Chatbox](https://github.com/Bin-Huang/chatbox)** | Electron（曾试 Tauri 又退回） | 轻量、零摩擦；⚠️ [退回 Electron 的原因值得研读](https://github.com/Bin-Huang/chatbox/issues/840) |
| **Jan** | **Tauri** ⭐ | **Tauri 旗舰 LLM 客户端**，离线 ChatGPT 替代品——Tauri 可行性的存在性证明 |
| **AnythingLLM** | Electron | 文档 RAG + 内置向量库 + agent |
| **chatmcp** | Flutter | 早期 MCP 协议客户端，UX 模式参考 |

## 三、Tauri 的机会窗口

Tauri vs Electron 的实测对比（2025 多来源一致）：

| 维度 | Tauri | Electron |
|------|-------|----------|
| 内存占用 | **少 ~58%** | 基准 |
| 安装包体积 | **小 ~96%**（用系统 WebView，不捆绑 Chromium） | 基准 |
| 启动时间 | **<0.5s** | 1-2s |
| 代价 | 依赖各平台 WebView（WebView2/WKWebView），渲染一致性需注意 | 一致性好但重 |

**对 WorkBuddy 的意义**：
- ChatGPT Desktop 的 3GB RAM 臃肿是真实且被广泛吐槽的痛点 → **Tauri 的轻量是可营销的正面差异**。
- Jan 已经证明 Tauri 跑 LLM 客户端 production-ready。
- 配套：[`tauri-plugin-llm`](https://github.com/crabnebula-dev/tauri-plugin-llm) 可在 Tauri 内做本地推理；[`dirvine/tauri-mcp`](https://github.com/dirvine/tauri-mcp) 提供 Tauri 的 MCP 集成。

⚠️ **Tauri 路线的教训**：Chatbox 从 Tauri 退回 Electron，说明 Tauri 的平台 WebView 差异、原生能力缺失、打包问题易踩坑。我们前期评估也因 pi 的 CORS 问题弃用了 Tauri，最终选 **deno desktop**（in-process bindings 绕开 IPC 与 WebView 限制，spike 验证通过，见 [03](./03-技术架构设计.md) 与 [07](./07-deno-desktop-spike验证.md)）。

## 四、关键技术趋势（影响产品设计）

| 趋势 | 现状 | 对 WorkBuddy 的影响 |
|------|------|---------------------|
| **MCP（Model Context Protocol）** | 第一年生态增长 407%；Windows 11 把 MCP 做进 OS 层；Anthropic .dxt 解决安装摩擦 | **table stakes**，必须 day-1 支持；但可靠性 > server 数量 |
| **本地优先 / 隐私** | 企业从 cloud-first 转 control-first；Recall 因隐私翻车 | 隐私是**核心产品需求**而非营销话术；敏感任务本地推理 |
| **Computer Use**（桌面控制） | Claude Computer Use、Copilot "computer use in agent" | 深度 OS 自动化的技术基座（我们的支柱②） |
| **本地 RAG** | AnythingLLM/Open WebUI 成熟；Cisco Local-RAG 是隐私参考设计 | 对个人文件做带引用的 RAG |
| **持久记忆** | ChatGPT 静默丢记忆是 top 投诉；用户要"可导出的自有记忆" | 一等公民的长期记忆 |

## 五、用户痛点 = 我们的机会

| 用户痛点（有证据） | WorkBuddy 的解法 |
|--------------------|------------------|
| **没有持久记忆 / 上下文丢失** | 一等公民的、用户自有、可导出的长期记忆 |
| **App 碎片化 / 上下文切换**（员工日均切 9.4 个 App，生产力损失达 40%） | 做连接层，把信息带到工作流内，而非"再多开一个 Tab" |
| **桌面 App 臃肿**（ChatGPT 3GB RAM） | Tauri 轻量是直接反制 |
| **AI 功能强行塞、还偷偷开启**（BBB 超 10 万 AI 投诉；JetBrains 删差评） | 克制——解决真实工作流问题；透明、opt-in |
| **回答泛泛、不认识我的数据** | 对用户**自己的文件/笔记/日程**做本地 RAG，带行内引用 |
| **没有真正的系统级存在**（用户主动请求 context-aware 的系统级 widget） | 常驻 overlay/热键 + 上下文感知（当前窗口、选区、屏幕） |
| **agent 不可靠 / Computer Use 经常失败** | pi 的"做减法"哲学 + 清晰的权限 UX + 沙箱 |
| **隐私不信任**（Recall 翻车） | 本地优先默认 + 数据流透明 + 敏感任务本地 |
| **薄壳套网页**（Gemini 被批"只是 portal"） | 做原生 agent runtime，不是聊天窗 |

## 六、WorkBuddy 产品定位

### 定位陈述（Positioning Statement）

> **面向中文知识工作者和个人效率极客**，WorkBuddy 是一款**本地优先的 AI 桌面智能体工作台**。它用**极简可靠的 pi agent 内核**驱动，能**真正操控你的电脑**、**读写编辑你的文档**，而不只是一个聊天窗口。**不同于**臃肿的 ChatGPT Desktop、绑定腾讯云生态的 WorkBuddy（腾讯）、或 Mac 限定的 Raycast，**我们更轻、更快、更可控、更可靠**。

### 目标用户画像

**主要：中文知识工作者**
- _谁_：产品经理、运营、市场、咨询、研究员、内容创作者
- _痛点_：每天处理大量文档/表格/PPT；重复性整理工作多；想用 AI 但不想数据上云；被多个工具切换淹没
- _场景_：周报月报、数据分析出表、PPT 制作、文档润色、信息整理、会议纪要转文档

**次要：个人效率极客（Prosumer）**
- _谁_：开发者、技术爱好者、自动化重度用户
- _痛点_：想要系统级自动化、Computer Use、高度可定制；嫌 ChatGPT/Claude Desktop 不够"能动手"
- _场景_：跨 App 编排、批量文件处理、自定义技能、本地 LLM

### 不做什么（明确边界）

- ❌ **不堆生态接入**：不做飞书/企微/钉钉的深度集成矩阵（与腾讯 WorkBuddy 区隔）
- ❌ **不做 ToB 团队版**（至少 MVP 阶段）：不做权限管理/审计/自托管
- ❌ **不做"情绪陪伴"**：拒绝 Inflection Pi 的失败路径
- ❌ **不做浏览器**：不与 Perplexity Comet/Dia 正面竞争

### 核心差异化（按优先级）

1. **🥇 pi 极简 & 可靠**（第一性差异）
   - 做减法：更少工具、更短 prompt、拒绝花哨 planning 链
   - 主打"稳定能跑通"，对冲整个行业的"agent 不可靠"痛点
   - 这是哲学层面的差异，最难被复制

2. **🥈 深度 OS 自动化**
   - Computer Use（截图+鼠标+键盘）、全局热键、屏幕/剪贴板感知、跨 App 编排
   - 做真正"能动手"的 agent，而非聊天窗

3. **🥉 文档引擎做到极致**
   - docx/xlsx/pptx/pdf 的本地读、写、**编辑**全打通
   - 不依赖 MS Office / WPS 安装
   - 用这个替代"飞书生态文档能力"的缺位

### 商业模式（初步）

- **开源核心**：agent 内核 + 基础文档引擎 + OS 自动化开源（GitHub-first，建立信任和社区）
- **付费 Pro**：高级技能包、云模型额度、高级 Computer Use 场景
- 暂不设企业版（与定位一致）
